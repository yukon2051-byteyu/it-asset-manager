## 1. 選定の方針

- 開発者はPython初学者のため、**覚えることが少なく、保守しやすい構成**を優先する（要件定義書 N-14）
- 社内ネットワーク内で、利用者300名・資産2,000件程度を扱えればよい（N-01、想定値）
- まず小さく動くものを作り、段階的に機能を追加する

## 2. 選定結果

| 役割 | 採用技術 | 選定理由 |
|---|---|---|
| プログラミング言語 | Python | 開発端末にインストール済み（3.15.0）。初学者向けの情報が多い |
| 画面（Webアプリ） | Streamlit | Pythonだけでブラウザの画面を作れる。HTML・JavaScriptを学ばなくてよい |
| データベース | SQLite | 1ファイルにデータを保存でき、サーバーの構築が不要。Pythonに標準で入っている |
| CSV・Excelの読み書き | pandas | 表形式データの定番ライブラリ。一括登録（F-15）とCSV・Excel出力（F-51）に使う |

## 3. 検討したが採用しなかった候補

| 候補 | 採用しなかった理由 |
|---|---|
| Flask / Django | 本格的なWebアプリを作れるが、HTML・テンプレート・ルーティングなどの理解が必要で、初学者の最初の一歩としては負担が大きい |
| Excelをデータ置き場にする | 複数人が同時に更新すると壊れやすく、現状の課題（更新漏れ・二重登録）を解決できない |
| MySQL / PostgreSQL | 大規模・多人数向けには適するが、データベースサーバーの構築・運用が必要。想定規模ではSQLiteで足りる |

## 4. 既知の弱点と対策

| 弱点 | 影響 | 対策 |
|---|---|---|
| Streamlitにはログイン機能が標準で付いていない | F-01（ログイン）、F-02（権限制御）を自作する必要がある | パスワードをハッシュ化して保存する簡易ログインを作る（N-05） |
| Python 3.15は新しく、ライブラリが未対応の可能性がある | インストールに失敗する可能性がある | インストール時に確認する。失敗した場合は対応済みのPythonの版を使うことを検討する |
| SQLiteは同時に大量の書き込みがあると待ちが発生する | 利用者が大幅に増えると遅くなる | 想定規模では問題ない見込み。将来必要になればPostgreSQLへの移行を検討する |
