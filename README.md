# 社内IT資産管理システム

PC・モニター・スマートフォン・ソフトウェアライセンスを1か所で管理する、社内向けのWebアプリです。
Excel台帳による手作業の管理を置き換えることを目指して開発しています。

> **開発の状況**：要件定義書の必須（Must）機能21件はすべて実装済みです。一部の任意（Should・Could）機能は未実装です。詳しくは「[主な機能](#主な機能)」と、[開発の振り返り](docs/retrospective.md)を参照してください。

## 採用担当者・レビューの方へ（お試しの手順）

1. 下の「[使い方（Windows）](#使い方windows)」の手順1〜3で、環境を作ってアプリを起動します
2. 手順2の `seed.py` を実行すると、**ログインできる5人のパスワードが画面に表示**されます（実行のたびにランダムに作られます）

| 社員番号 | 権限 | お試しいただける内容 |
|---|---|---|
| E0001 | IT管理者 | 資産の登録・CSV一括登録・割当・申請の承認・ライセンス・利用者管理・操作履歴 |
| E0002〜E0005 | 一般社員 | 自分の資産の確認、貸出・返却・故障・紛失の申請、棚卸の回答（E0001で棚卸を開始したあと） |

3. **E0006〜E0100 の95人は、わざと「パスワード未発行」にしています**。「アカウントはあるが、初期パスワードはまだ本人に渡していない」状態を再現したもので、そのままではログインできません
   - ログインさせたい場合は、E0001でログインし、「利用者管理」→「変更・退職・パスワード」で社員を選んで「パスワードを再発行する」を押してください。表示されたパスワードでログインできます
   - 一覧の「パスワード」列で、発行済か未発行かを確認できます
4. 登場する人名・会社名・製品名・メールアドレス・電話番号は、すべて架空のものです

## 解決したい業務課題

IT資産をExcelの台帳で管理している職場で、次のような課題が起きることを想定しています。

| 課題 | このシステムでの解決方法 |
|---|---|
| 台帳の更新漏れ・二重登録が起きる | データベースで一元管理し、資産番号・シリアル番号の重複を登録時に防ぐ |
| 「誰が・どの機器を使っているか」をすぐ答えられない | 機器と利用者をひも付けて、一覧で絞り込めるようにする |
| ライセンスの保有数と利用数が合わない | 割当の記録から残数を自動で計算する |
| 貸出・返却の記録が残らない | 申請・承認をシステム上で行う（予定） |
| 棚卸に時間がかかる | 社員が自分の機器ごとに画面で「ある／ない」を回答し、未回答と差異を一覧で確認できるようにする |

※ 上記は一般的な業務を想定した課題です。特定の企業での実測や導入の実績ではありません。

## 使い方（Windows）

### 1. 環境を作る（初回のみ）

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. サンプルデータを入れる（初回のみ）

```powershell
.\.venv\Scripts\python.exe seed.py
```

架空の社員5名・機器10台・ライセンス3種類が登録されます。データがすでにある場合は、この基本のサンプルは登録しません。

あわせて、架空の社員を合計100人（E0006〜E0100、8部署）になるまで追加します。すでにある社員番号は飛ばすので、何度実行しても二重登録しません。追加した社員のパスワードは「未発行」で、そのままではログインできません。ログインさせる場合は、IT管理者が「利用者管理」でパスワードを再発行してください。

実行すると、基本の5名のログイン用パスワードが**1回だけ**表示されます。パスワードは実行のたびにランダムに作られ、ソースコードには書かれていません。

```
  E0001  佐藤 花子（IT管理者）  ************
  E0002  鈴木 一郎（一般社員）  ************
  ...
```

パスワードを忘れた場合は、IT管理者が「利用者管理」から再発行できます。IT管理者自身のパスワードがわからない場合は、`assets.db` を削除してから `seed.py` を実行し直してください（データはサンプルの状態に戻ります）。

環境変数 `ASSETS_DB_PATH` にファイルの場所を設定すると、`assets.db` の代わりにそのファイルを使います（本番のデータと分けて試すときに使います）。

### 3. アプリを起動する

```powershell
.\.venv\Scripts\streamlit.exe run app.py
```

ブラウザで http://localhost:8501 が開きます。社員番号と、手順2で表示されたパスワードでログインしてください。
- **一般社員**（例：E0002）：「自分の資産」に、自分が使っている機器とライセンスが表示されます。「申請」で貸出・返却・故障・紛失を申請し、「申請の状況」タブで結果を確認できます
- **IT管理者**（E0001）：「資産一覧」で、全機器を種別・状態・部署・キーワードで絞り込んで表示し、CSV・Excelでダウンロードできます。一覧の下で機器を選ぶと、その機器の詳細と履歴が表示されます。「集計レポート」で、台数や利用率をグラフで確認できます。「資産登録」で新しい機器を登録し、「資産更新」で登録済みの機器の情報を変更できます。「割当・返却・廃棄」で機器の状態を変えられます。「CSV一括登録」では、`samples/` の試し用ファイルで取り込みを試せます（`devices_import_sample.csv` は正しいデータ、`devices_import_error_sample.csv` は誤りを含むデータです）。「ライセンス」では、一覧・割当と解除・登録・変更ができます。「申請の承認」で、社員からの申請を承認・保留・却下できます。「棚卸」で、棚卸の開始・進み具合の確認・差異の対応・完了ができます。「利用者管理」で、社員の登録・退職処理・パスワード再発行ができます。「操作履歴」で、誰がいつ何を変えたかを確認できます（例：キーワードに「PC-0001」と入れると、その機器の利用者の移り変わりがわかります）

終了するときは、ターミナルで `Ctrl + C` を押します。

## 設計で工夫した点

- **データを1か所でだけ持つ**：ライセンスの残数は保存せず、割当の記録から毎回計算します。残数を別に保存すると、更新漏れで数字が食い違うためです
- **入力ミスは2段構えで防ぐ**：画面で登録するときに、わかりやすいメッセージで入力ミスを知らせます。さらにデータベース自体にもルールを設けているので、プログラムに不具合があっても重複・空欄・決められていない値は保存されません
- **状態は自由に書き換えさせない**：資産の更新画面では、状態（使用中・廃棄済など）と利用者は変更できません。状態は割当・返却・廃棄などの業務の操作でだけ変わるようにし、「利用者がいないのに使用中」といった矛盾を防ぎます。操作できる状態の組み合わせは1つの表（`devices.TRANSITIONS`）にまとめ、要件定義書の状態遷移図と対応させています
- **申請の承認と機器の状態を同時に変える**：承認すると、申請の状態と機器の状態（貸出中・修理中など）を1つのトランザクションで更新します。機器の状態を変えられないとき（すでに使用中など）は、申請も「承認待ち」のまま残り、片方だけが変わることはありません
- **同時操作に備える**：状態を変えるときは「画面を開いたときの状態のままなら更新する」という条件を付けています。ほかの管理者が先に変えていた場合は、上書きせずに止めます。ライセンスの割当では「追加したあとに数え直し、保有数を超えていたら取り消す」順番にして、同時に割り当てても保有数を超えないようにしています
- **台帳の移行で迷わせない**：CSV一括登録では、1件でも誤りがあれば全件を取り込まず、すべての誤りを行番号つきで一度に表示します。「どの行が入ったか」を調べる手間をなくし、直して取り込み直すだけで済むようにしました。Excelで保存したShift_JISのCSVもそのまま読めます。また、すべての列を文字として読み込み、IMEIなどの番号が数値に変換されて桁や先頭の0が失われないようにしています
- **色だけに頼らないグラフ**：グラフの色は、検証用のプログラムで「色覚の違いがあっても隣どうしの色を見分けられる」ことを確かめた配色を使い、状態ごとに色を固定しています。どのグラフにも同じ内容の表を添え、ライセンスの注意（期限切れなど）は色ではなく文字で示します
- **検索の入力ゆれを吸収する**：キーワードは全角を半角にそろえてから探すので、「ＰＣ－０００１」でも見つかります。また、入力された `%` や `_` はSQLの特別な記号としてではなく、ただの文字として探します
- **資産番号を使い回さない**：番号は自動で発行し、廃棄した機器の番号も欠番として残します。過去の記録と新しい機器が混ざらないようにするためです
- **保存する値と表示する名前を分ける**：状態は `in_use` などのコードで保存し、画面では「使用中」と表示します。表示名を変えても保存済みのデータに影響しません
- **機器を1つのテーブルにまとめる**：PC・モニター・スマートフォンを1つの表にまとめ、「ある社員の機器をすべて見る」処理を簡単にしました。種別によって空欄の列ができる点は許容しています
- **パスワードを安全に扱う**：パスワードはそのまま保存せず、社員ごとに違うランダムな値（ソルト）を混ぜて60万回変換した文字列だけを保存します（Python標準の `hashlib.pbkdf2_hmac`）。ログインに失敗したときは「社員番号**または**パスワードが違います」とだけ表示し、どちらが違うかは伝えません
- **操作履歴を変更と同時に、消せない形で残す**：変更と履歴の記録は同じトランザクションで行うので、「変更されたのに履歴がない」ことは起きません。さらにデータベースのトリガーで履歴の書き換え・削除を禁止し、プログラムに不具合があっても改ざんできないようにしています。状態の変更では利用者の変化も記録するので、棚卸で記録と現物が合わないときに「誰がいつまで使っていたか」を追えます
- **管理者の締め出し事故を防ぐ**：自分自身の退職処理や権限の引き下げ、IT管理者が1人もいなくなる変更はできないようにしました。また、画面を操作するたびに在籍と権限を確かめ直すので、ログイン中に退職処理された人は次の操作でログアウトされます
- **データを残したまま構造を移行する**：機能の追加で操作履歴のテーブルのルールを変える必要が出たため、起動時に古い構造を検知し、履歴を残したままテーブルを作り直す処理（マイグレーション）を入れました
- **データを物理削除しない**：廃棄した機器も記録として残します（監査に対応するため）

## 今後の改善予定

**発展として考えていること：Active Directory との連携**（開発者の発案）

社内のPCは、ふつうActive Directory（AD：Windowsの社内ネットワークで、アカウントやPCを一元管理する仕組み）に登録されています。ADと連携すると、次のことができるようになります。

- ADのPCの一覧と台帳を照らし合わせ、「ADにあるのに台帳にないPC（登録漏れ）」「台帳にあるのにADにないPC（廃棄漏れ・紛失の疑い）」を自動で見つける
- PCが最後にログオンした日時から、長く使われていないPCを見つける
- 社員のログインを、会社のアカウント（AD／Microsoft Entra ID）で行う（要件定義書の未確定事項 Q-03）

実現には、ADを読み取るための専用アカウントや、どの項目を取り込むかなどを、情報システム部門と決める必要があります。

**そのほかの改善**

1. 「自分の資産」に、自分のPCに割り当てたライセンス（ウイルス対策ソフトなど）も表示する
2. パスワードの変更、ログイン失敗が続いたときのロック
3. Excelファイル（.xlsx）の直接取り込み
4. メール通知：申請・承認、返却予定日、ライセンス期限（メールサーバーの確認が必要。要件定義書 Q-04）
5. ソフトウェアの利用申請
6. ログイン・ログイン失敗の記録
7. 部署を一覧（マスタ）から選ぶ形にする（「営業」と「営業部」のような表記ゆれを防ぐ）
